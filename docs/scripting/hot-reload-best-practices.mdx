This guide summarizes the recommended usage patterns for hot reload, to keep iteration fast and reloads stable. Scripts are compiled by the compile server, outside the editor process: see [Compile server](../contributing/compile-server.mdx).

## Public export shape for fast invocation

- Exports are `public static int` methods with no parameters.
- Keep names stable. Prefer fully qualified names (`Namespace.Type.Method`) when querying.
- Use the `HotReloadHelper` facades:
  - `TryQuery(string name, out ulong token, ulong domain = 0)`
  - `TryInvoke(ulong token, ulong domain = 0)`
- Return `ScriptingOpResult.Ok` (0) on success; use the negative codes from `ScriptingOpResult` for errors.

## Token lifecycle and domains

- Tokens are stable within a domain for a given export; they may become invalid after swaps.
- After `SwapPreloadedContext` or `LoadCompiledAssembly`, query the tokens again.
- Domain 0 means "current domain". `HotReloadManager` keeps a positive domain id per loaded context.

## Query and invoke performance

- `QueryExportInDomain` uses a prebuilt index (full name and simple name) for constant-time lookup after a load or swap.
- Query by full name when possible; simple names are supported, but the first match wins.
- Cache tokens on the caller side, and invoke by token on the hot path.

## Assembly loading and swapping

For the fastest swaps:

1. `PreloadAssemblyContext(byte[] asm, byte[]? pdb)`
2. `SwapPreloadedContext()`

Preloading does all the heavy work (context creation, load) off the main thread; the swap is atomic and fast. Loading by file path is supported, but loading from a stream or bytes avoids file locks.

## Environment flags

- `GE_HOTRELOAD_VERBOSE=1` enables info-level logs for `HotReloadManager`. The default is quiet; warnings and errors still print.
- `GE_HRM_PATH` lets tests and tools locate the built `HotReloadManager` assembly.

## Error handling

- Methods return `int` codes; 0 is success. `CoreBridge` maps them to its `ScriptingOpResult`, whose values are `GE_Result`'s.
- Common failure codes include `Fail` (-1), `InvalidArg` (-2), `NotFound` (-3) and `NotInitialized` (-4); a missing script assembly file is `NotFound`.

## Testing patterns

- Use `HotReloadHelper` in tests to reduce reflection and boilerplate.

## Diagnostics

- `HotReloadManager` keeps its logs minimal by default, for clean test output.
- Enable verbose mode during an investigation; leave it off for normal runs to avoid the overhead.
